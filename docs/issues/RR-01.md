# RR-01: Extract and explain a reusable profile card

Status: open local draft; not a published GitHub issue.

Milestone: 1

Planned owner: @lakerss6 (A, you); reviewer: @joewahy (B). Recorded locally; not assigned on GitHub.

## Goal

Extract the existing profile article into a typed component without changing its visible behavior.

## Dependencies

Starter only

## Starting points

src/app/page.tsx; src/features/contacts/types.ts

## Acceptance criteria

- [ ] Pass one PersonSummary as a prop; keep stable person IDs as keys.
- [ ] Render all three demo profiles and preserve accessible headings and mobile layout.
- [ ] Document Server versus Client Components in a short PR learning note.

## Guided first steps for beginners

1. Find the `demoPeople.map(...)` expression in page.tsx and identify the repeated article.
2. Create a component file that receives one PersonSummary. Move only the article into it.
3. Replace the inline article with that component. Compare the page before and after.

Work on one step at a time. Ask for explanations or hints when stuck; the debugging exercise is a learning prompt, not a deliberately planted bug.

## Learning objective

Props, component boundaries, array rendering, and Server Components.

## Debugging exercise

Temporarily misspell a prop on a disposable branch; explain the compiler error, then restore it.

## Verification and handoff

Run `npm run typecheck` and `npm run build`. Record relevant manual steps and any focused tests. Have the reviewer reproduce one edge case. Explain one implementation decision in your own words.

## Out of scope

Search, new dependencies, persistence.
