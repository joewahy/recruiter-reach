# RR-06: Save contacts into named lists with demo persistence

Status: open local draft; not a published GitHub issue.

Milestone: 3

Planned owner: @lakerss6 (A, you); reviewer: @joewahy (B). Recorded locally; not assigned on GitHub.

## Goal

Save profile references and revealed demo results into lists that survive a browser reload.

## Dependencies

Milestone 2; coordinate IDs with RR-05

## Starting points

New contacts/list feature modules; use IDs rather than duplicated profile objects

## Acceptance criteria

- [ ] Create, rename, and remove lists; add and remove contact membership.
- [ ] Prevent duplicate memberships; removing membership does not delete a contact.
- [ ] Persist synthetic user state using a versioned app-specific localStorage key.
- [ ] Recover from missing, malformed, and unavailable storage with a visible explanation.
- [ ] Handle hydration without losing existing data; disclose that storage is local to one browser.

## Guided first steps for beginners

1. Model one list as an ID, name, and collection of contact IDs.
2. Make adding/removing membership work in memory before using storage.
3. Add a versioned storage helper and recovery behavior, then test reloads.

Work on one step at a time. Ask for explanations or hints when stuck; the debugging exercise is a learning prompt, not a deliberately planted bug.

## Learning objective

Normalized state, effects, storage validation, and hydration.

## Debugging exercise

Corrupt the app storage key and try storage-disabled mode; inspect recovery behavior.

## Verification and handoff

Run `npm run typecheck` and `npm run build`. Record relevant manual steps and any focused tests. Have the reviewer reproduce one edge case. Explain one implementation decision in your own words.

## Out of scope

Production privacy boundary, multi-user sharing, or PostgreSQL.
