# RR-03: Implement text search with a clear empty state

Status: open local draft; not a published GitHub issue.

Milestone: 2

Planned owner: @lakerss6 (A, you); reviewer: @joewahy (B). Recorded locally; not assigned on GitHub.

## Goal

Let a job seeker search profile names, titles, and companies in the synthetic directory.

## Dependencies

RR-01 and RR-02

## Starting points

src/features/contacts/; src/app/page.tsx

## Acceptance criteria

- [ ] Agree on a search component boundary before RR-04 begins.
- [ ] Match case-insensitively and trim surrounding whitespace.
- [ ] Show all results for an empty query and an honest result count.
- [ ] Show a useful no-results state with a working reset action.
- [ ] Preserve the text query in the URL so reload and a shared link retain it.

## Guided first steps for beginners

1. Write down three sample queries and expected matching names before coding.
2. Implement a small pure matching function first, separate from the UI.
3. Connect a labeled input, then add the empty state and URL handling as separate steps.

Work on one step at a time. Ask for explanations or hints when stuck; the debugging exercise is a learning prompt, not a deliberately planted bug.

## Learning objective

Derived state, form controls, URL parameters, and matching functions.

## Debugging exercise

Investigate mixed case, whitespace-only queries, and names with spaces.

## Verification and handoff

Run `npm run typecheck` and `npm run build`. Record relevant manual steps and any focused tests. Have the reviewer reproduce one edge case. Explain one implementation decision in your own words.

## Out of scope

Lookup, saved contacts, fuzzy ranking.
