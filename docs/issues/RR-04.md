# RR-04: Add composable role and location filters

Status: open local draft; not a published GitHub issue.

Milestone: 2

Planned owner: @joewahy (B, your friend); reviewer: @lakerss6 (A). Recorded locally; not assigned on GitHub.

## Goal

Narrow text-search results by role and person location without losing URL state.

## Dependencies

RR-03 search boundary merged

## Starting points

Search component and filter utility agreed in RR-03

## Acceptance criteria

- [ ] Use OR within a multi-select category and AND between categories and the text query.
- [ ] Label all controls and make reset clear every filter.
- [ ] Handle unknown URL filter values gracefully.
- [ ] Retain selections through reload and browser back/forward.
- [ ] If pagination is introduced, reset it when a filter changes.

## Guided first steps for beginners

1. Draw how the text query and selected role/location combine on paper.
2. Add one role filter and verify it together with text search.
3. Add location and URL synchronization next; inspect browser back/forward behavior.

Work on one step at a time. Ask for explanations or hints when stuck; the debugging exercise is a learning prompt, not a deliberately planted bug.

## Learning objective

Predicate composition, URL-driven state, and keyboard-accessible inputs.

## Debugging exercise

Compare each individual predicate with the combined result for recruiter + Seattle.

## Verification and handoff

Run `npm run typecheck` and `npm run build`. Record relevant manual steps and any focused tests. Have the reviewer reproduce one edge case. Explain one implementation decision in your own words.

## Out of scope

Company-headquarters filtering or provider APIs.
