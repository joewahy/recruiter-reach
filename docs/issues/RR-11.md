# RR-11: Prepare due follow-ups and enforce stop rules

Status: open local draft; not a published GitHub issue.

Milestone: 6

Planned owner: @lakerss6 (A, you); reviewer: @joewahy (B). Recorded locally; not assigned on GitHub.

## Goal

Create ordered follow-up drafts that each need approval and stop when outreach is no longer eligible.

## Dependencies

Milestone 5

## Starting points

New sequences domain; existing approval/simulation service

## Acceptance criteria

- [ ] Agree on delay defaults and business-day calendar before implementation.
- [ ] Use a controllable demo clock with UTC storage and IANA timezone calculations.
- [ ] Generate due drafts without auto-approving or auto-sending.
- [ ] Support pause/resume/stop and simulated reply, bounce, and opt-out events.
- [ ] Invalidate unsent approvals on a stop and recheck eligibility at dispatch.
- [ ] Deduplicate demo events; add tests for reply-before-dispatch, repeat events, and DST boundaries.
- [ ] Clearly disclose that demo scheduling runs only while the local app is open.

## Learning objective

Time modeling, state transitions, race conditions, and fake-clock tests.

## Debugging exercise

Create a due approved message then inject a reply before dispatch; explain where the final guard belongs.

## Verification and handoff

Run `npm run typecheck` and `npm run build`. Record relevant manual steps and any focused tests. Have the reviewer reproduce one edge case. Explain one implementation decision in your own words.

## Out of scope

Browser timers as durable production scheduling, live webhooks, or automatic sending.
