# RR-10: Approve each message and simulate delivery safely

Status: open local draft; not a published GitHub issue.

Milestone: 5

Planned owner: @lakerss6 (A, you); reviewer: @joewahy (B). Recorded locally; not assigned on GitHub.

## Goal

Make approval an explicit action on one exact message and simulate its delivery once.

## Dependencies

RR-09 shared snapshot contract; implement after composer integration

## Starting points

New approval and simulated delivery domain service

## Acceptance criteria

- [ ] Show full sender, recipient, subject, and body before approval.
- [ ] Bind approver and timestamp to an immutable snapshot/version.
- [ ] Require new approval after any message-field edit.
- [ ] Use an explicitly labeled Simulate send action; there is no real email provider.
- [ ] Recheck approval and recipient eligibility immediately before simulation.
- [ ] Deduplicate repeated delivery attempts and distinguish simulated acceptance from delivery evidence.
- [ ] Add focused regression tests for stale approval and repeated attempts.

## Learning objective

State machines, authorization concepts, idempotency, and regression tests.

## Debugging exercise

Approve then edit recipient, and double-click delivery; neither stale approval nor duplicate dispatch may succeed.

## Verification and handoff

Run `npm run typecheck` and `npm run build`. Record relevant manual steps and any focused tests. Have the reviewer reproduce one edge case. Explain one implementation decision in your own words.

## Out of scope

Automatic approvals, blanket approvals, or real sending.
